# Practice 9: Create database and check integrity

## Опис ситуації

Потрібно спроєктувати базу даних для невеликого інтернет-магазину. Система має зберігати інформацію про клієнтів, товари, замовлення та товари в замовленнях.

## Додаткова інформація

Під час створення зовнішніх ключів (`FOREIGN KEY`) у PostgreSQL можна налаштовувати поведінку бази даних при видаленні записів із батьківської таблиці за допомогою параметра `ON DELETE`.

У цій практичній роботі необхідно самостійно дослідити такі варіанти:

### ON DELETE CASCADE

Якщо запис із батьківської таблиці видаляється, усі пов'язані записи в дочірній таблиці також видаляються автоматично.

Приклад:

- видалення клієнта може автоматично видаляти всі його замовлення;
- видалення замовлення може автоматично видаляти всі товари в цьому замовленні.

### ON DELETE RESTRICT (або аналогічна поведінка)

Якщо на запис існують посилання з інших таблиць, його видалення забороняється.

Приклад:

- якщо товар уже використовується в замовленні, база даних не повинна дозволяти його видалити.

### Ваше завдання

Перед початком реалізації знайдіть у документації PostgreSQL:

1. Як працює `ON DELETE CASCADE`.
2. Як реалізувати заборону видалення запису, якщо на нього є посилання з інших таблиць.
3. Для яких зв'язків у цій практичній роботі доцільно використовувати кожен із цих підходів.

Отримані знання необхідно застосувати під час створення структури бази даних.

# Завдання

Створіть базу даних, яка містить такі таблиці:

## 1. customers

Зберігає інформацію про клієнтів.

### Поля

- `customer_id` — первинний ключ
- `first_name` — ім’я клієнта
- `last_name` — прізвище клієнта
- `email` — унікальний email
- `created_at` — дата створення клієнта

### Обмеження

- `email` не може повторюватися
- `first_name`, `last_name`, `email` не можуть бути `NULL`

---

## 2. products

Зберігає інформацію про товари.

### Поля

- `product_id` — первинний ключ
- `product_name` — назва товару
- `price` — ціна товару
- `stock_quantity` — кількість товару на складі

### Обмеження

- `price` має бути більше 0
- `stock_quantity` не може бути менше 0
- `product_name` не може бути `NULL`

---

## 3. orders

Зберігає інформацію про замовлення.

### Поля

- `order_id` — первинний ключ
- `customer_id` — зовнішній ключ на таблицю `customers`
- `order_date` — дата замовлення
- `status` — статус замовлення

### Обмеження

- `customer_id` не може бути `NULL`
- `status` може мати лише значення:
  - `new`
  - `paid`
  - `shipped`
  - `cancelled`
- якщо клієнта видаляють, всі його замовлення мають видалятися автоматично

---

## 4. order_items

Зберігає товари, які входять до замовлення.

### Поля

- `order_item_id` — первинний ключ
- `order_id` — зовнішній ключ на таблицю `orders`
- `product_id` — зовнішній ключ на таблицю `products`
- `quantity` — кількість товару
- `price_at_order` — ціна товару на момент замовлення

### Обмеження

- `quantity` має бути більше 0
- `price_at_order` має бути більше 0
- якщо замовлення видаляється, всі його товари мають видалятися автоматично
- якщо товар використовується в замовленні, його не можна видалити

# Що потрібно зробити

1. Створити всі таблиці.
2. Додати всі потрібні:
   - `PRIMARY KEY`
   - `FOREIGN KEY`
   - `UNIQUE`
   - `NOT NULL`
   - `CHECK`
     обмеження.
3. Реалізувати каскадне видалення:
   - при видаленні клієнта мають видалятися його замовлення;
   - при видаленні замовлення мають видалятися всі записи з `order_items`.
4. Заборонити видалення товару, якщо він уже є в замовленні.
5. Додати тестові дані:
   - мінімум 3 клієнти;
   - мінімум 5 товарів;
   - мінімум 4 замовлення;
   - мінімум 8 записів у `order_items`.
6. Перевірити роботу обмежень за допомогою SQL-запитів.
